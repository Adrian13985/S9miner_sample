# 2026-09-23 P01 UART 独立复测

- 辅助程度：先闭卷回答，随后使用分步问题和代码骨架纠正
- 闭卷表现：能判断当前接收路径为轮询，并说明无条件调用 `inbyte()` 会在 RX FIFO 为空时阻塞同一执行流；最初仍把 `inbyte()` 说成读取字符串
- 指针与容量：最初把 `*p` 解释成整个字符串、把 `&p` 解释成缓冲区地址，并尝试从指针推导容量；经分步纠正后能答出 `p == &buf[0]`、`*p == buf[0]`、`strlen(buf) == 3`、数组容量为 8，但曾把 `&p` 的类型答成 `char`
- 最小重写：第一次无参考重写仍使用错误的 `while(is_rec_data)` 结构、缺少字符常量和状态参数；给出主循环骨架后能正确填入 `XUartPs_IsReceiveData()`、`inbyte()`、`command`、`&count` 和 `&periodic_print_enabled`
- 因果解释：经追问后能说明 `command` 按值传递，而 `count` 和打印状态通过地址传递，使处理函数能修改 `main()` 中的对象
- 建议等级：P02 UART 与 C01 均保持 L1；路径模型接近通过，但最小实现和容量契约尚无无提示证据
- 延迟复测：下次不提供函数骨架，独立写出非阻塞主循环；用新的数组容量题区分 `sizeof`、`strlen`、指针大小和显式 capacity
