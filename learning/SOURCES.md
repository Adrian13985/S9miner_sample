# 资料入口与来源策略

完整调研结果已落在以下文件：

- `research/RESOURCE_CATALOG.md`：已核验的教程、文档、代码仓库、版本与用途；
- `research/COMPARATIVE_STUDY.md`：为什么选择当前学习顺序，以及从各套完整课程吸收什么；
- `research/BOARD_CAPABILITY_MATRIX.md`：本板可做什么、哪些仍需实测、每类实验风险；
- `PROJECT_BACKLOG.md`：每个项目实际采用的参考种子、迁移题和验收。

## 来源优先级

1. 本板原理图、实测信号和当前工程配置；
2. 器件数据手册、Zynq-7000 TRM、Xilinx/AMD对应版本工具文档；
3. ARM Cortex-A9、GIC和AMBA AXI架构规范；
4. Xilinx BSP驱动源码、头文件和官方示例；
5. FatFs等上游组件的官方文档；
6. 高质量课程、论坛和博客，仅用于补充直觉与故障经验；
7. 当前仓库教程和AI解释，必须能回溯到以上证据。

## 版本与取用规则

- 裸机代码优先使用 `Xilinx/embeddedsw` 的 `xilinx-v2017.4` 标签，并与本项目实际 BSP 交叉检查。
- Linux、U-Boot、设备树固定同一发行线；不能把 2017.4 工程与当前 `master` 的 API 和 DTS 直接混合。
- 其他开发板只复用原理、结构和纯算法；PS preset、DDR、MIO、XDC、时钟、复位、地址和外设芯片全部重新确认。
- 不批量搬入大型仓库。开始具体项目时只取最小代码，记录 URL、标签/提交、原路径、许可证和本板适配差异。
- 许可证不清晰的课程代码只能阅读后独立重写。

## 引用要求

- 硬件管脚和电压必须引用原理图页或实测证据。
- 寄存器位、复位值和时序要求必须引用对应器件/驱动版本。
- 如果只能依据生成代码或当前例程推断，要明确标记“项目推断”，不能写成通用事实。
