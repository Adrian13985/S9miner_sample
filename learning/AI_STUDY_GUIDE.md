# 如何与 AI 配合学习

本指南用于把 AI 约束为“导师、实验设计者和进度管理员”，而不是替学习者包办代码。建议从 `S9miner_sample` 目录开始对话，并在涉及本项目学习时显式使用 `$s9-zynq-mentor`。

## 最少查阅路径

日常不需要从头精读所有文档：

```text
INDEX.md
  -> ROADMAP.md：判断当前阶段
  -> PROJECT_BACKLOG.md：选择具体项目
  -> MASTERY.md + REVIEW_QUEUE.md：确定本次真实缺口
  -> 做实验并留下证据
  -> 更新 PROGRESS/MASTERY/MISCONCEPTIONS/REVIEW_QUEUE
```

需要扩展新主题时，再查 `CURRICULUM.md`、`research/RESOURCE_CATALOG.md` 和本板能力矩阵。

## 第一次开始

```text
$s9-zynq-mentor

请读取 learning/INDEX.md、learning/PROGRESS.md、learning/MASTERY.md、
learning/REVIEW_QUEUE.md 和 learning/assessments/BASELINE.md。

先不要直接讲课，也不要修改代码。请分批对我进行基线诊断，
每次只问 3～5 个问题。我回答后判断我是：
1. 真正理解；
2. 只记得结论；
3. 存在错误模型；
4. 完全没接触。

诊断后只安排一个 60～90 分钟的学习任务，
说明能力节点、先修、风险和最终需要留下的证据。
```

## 开始一次普通学习会话

```text
$s9-zynq-mentor

请读取当前进度、掌握度和复习队列，根据先修关系选择今天最合适的任务。

要求：
- 只安排一个 60～90 分钟的目标；
- 先检查前置知识和旧知识；
- 先让我预测，不要立即给完整答案；
- 从物理信号、硬件、寄存器/协议、CPU、驱动讲到程序现象；
- 设计一个故障注入和一个改变约束的迁移题；
- 告诉我最终需要保存哪些证据。
```

## 解释代码时

```text
$s9-zynq-mentor

请讲解这个文件，但不要逐行翻译。按照以下路径解释：
外部输入或数据
-> 管脚/控制器/PL逻辑
-> 时钟、复位、FIFO、寄存器或协议
-> AXI、Cortex-A9、Cache/DDR
-> BSP驱动
-> C程序状态
-> 最终可观测现象。

请区分本板实测、文档事实和待验证推断；说明关键假设、典型失败模式，
并让我预测删掉或修改一个关键条件后的结果。
```

## 调试时

```text
$s9-zynq-mentor

不要直接修改代码。先让我提供正常基线、实际现象、完整日志、预期结果和最近改变。
然后按硬件连接、时钟/复位、寄存器/协议、驱动、C程序逐层缩小范围。
每次只设计一个能区分两个假设的实验。
```

## 需要 AI 协助写代码时

```text
$s9-zynq-mentor

本任务使用“部分脚手架”模式：
- 先让我写接口、状态和伪代码；
- 第一轮只给函数框架和关键提示；
- 我尝试后再指出错误；
- 最后安排一次不看答案的最小重写；
- 把成果标记为“辅助完成”，不要直接判定为 L2。
```

## 一次会话的节奏

```text
旧知识检索
-> 预测现象
-> 建立底层因果模型
-> 亲自修改或搭建
-> 运行并记录
-> 主动制造故障
-> 改变约束完成迁移
-> 无提示验收
-> 安排延迟复测
```

AI 可以给提示、资料、检查方法和脚手架；学习者负责预测、上板、记录现象、独立解释和重写。AI 生成并成功运行的完整代码只能算辅助证据。

## 学习结束时

```text
$s9-zynq-mentor

请验收本次学习。先让我在不看代码的情况下：
1. 解释完整因果链；
2. 预测改变条件后的结果；
3. 定位一个你设计的故障；
4. 写出最小实现或伪代码。

再根据实际证据更新 learning/PROGRESS.md、learning/MASTERY.md、
learning/MISCONCEPTIONS.md 和 learning/REVIEW_QUEUE.md。
标明辅助程度，不要因为程序成功运行就自动提升等级。
```
